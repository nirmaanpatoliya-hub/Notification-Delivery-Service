Send Notification

Enqueue a new email or SMS notification into the outbox for background delivery.

Compose Notification POST /api/messages
Transactional messages (OTPs, order alerts) are always processed before marketing campaigns.
Must match email format (e.g., user@shop.example). Max 254 characters.
0 / 150
Required for email. 1 to 150 characters.
0 / 2,000
Email body must be between 1 and 2,000 characters.

Sending the exact same key with the same payload returns the original message without duplicating it.
How DakGhar Handles S1
1. Instant SQLite Save

When you click Send, the API validates the inputs and saves the message into the SQLite messages table as pending before returning 201 Created.

2. Background Worker Pick-Up

The background worker checks the database every second, claims due messages (transactional first), and attempts delivery through the mock providers.

3. Testing Provider Outages

Try switching on an outage in Providers & Worker and then sending messages here to watch DakGhar automatically failover to the backup provider!

API Key Settings

DakGhar enforces permissions using two separate secret keys sent in request headers. Keys are stored only in sessionStorage for this browser session and sent to the DakGhar API in request headers (X-Api-Key or X-Admin-Key). They are cleared when the browser tab closes.

No Sender Key
Used for enqueuing messages and viewing the outbox. Sent exclusively via the X-Api-Key header.
No Admin Key
Used for worker pause/resume, single tick, provider outage switches, and database reset. Sent exclusively via the X-Admin-Key header.
